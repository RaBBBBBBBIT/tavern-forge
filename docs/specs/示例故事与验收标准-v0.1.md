# 示例故事与验收标准

- 版本：0.1
- 日期：2026-09-23
- 状态：运行时和记忆系统的共用测试草案。
- 依赖：[叙事运行时规格](./叙事运行时规格-v0.1.md)、[记忆与上下文材料规格](./记忆与上下文材料规格-v0.1.md)、[接口契约规格](./接口契约规格-v0.1.md)、[数据模型规格](./数据模型规格-v0.1.md)、[前端交互规格](./前端交互规格-v0.1.md)。
- 范围：用简单故事验证多角色、角色记忆、Turn 提交、分支、插件和自托管边界。

## 1. 示例故事

### 1.1 人物和秘密

```text
Alice：知道钥匙藏在酒馆书架后面。
Bob：不知道钥匙的位置，但怀疑 Alice 拿走了钥匙。
Carol：不在酒馆，只能通过别人告诉她的内容获得信息。
```

### 1.2 场景

```text
地点：酒馆后门
时间：午夜
在场：Alice、Bob
公开物品：一张木桌、一盏油灯、一个书架
隐藏事实：钥匙在书架后面
```

### 1.3 主要流程

1. 用户输入触发 `Bob -> Bob -> Alice -> Bob`。
2. Alice 的回复可以依据 Bob 在当前 Turn 中已经说出的、且 Alice 能听到的内容。
3. Bob 不能因为 Director 知道秘密，就自动知道钥匙的位置。
4. 用户可以在同一 Turn 里发送角色输入和作者指令。
5. 用户可以临时接管 Bob，再显式交还控制。
6. 第三个 Beat 生成中断时，系统必须保留临时前缀，并要求继续、采纳完整前缀或完整回退。
7. 从某个已提交 Turn 创建分支后，父分支之后的内容不能出现在子分支。
8. 聊天模式切换到小说模式只改变输入和展示方式，不改变既有事实和角色记忆。

## 2. 验收场景

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| A01 | 一条输入触发 Bob、Bob、Alice、Bob | 四次发言顺序正确，无强制轮流；Director 不逐句审批 |
| A02 | Alice 依据 Bob 前一句作答 | 读取当前 Turn 内已接受且对她可见的前一句；不依据尚未执行的计划预测台词 |
| A03 | Alice 知道秘密，Bob 不知道 | Bob 的记忆、历史、世界书、工具结果和 ActorBrief 均不含未授权秘密 |
| A04 | 用户读取 Alice 的秘密状态 | 不改变任何 Actor 的知识状态 |
| A05 | Bob 被告知假消息 | 记录 Bob 的信念及来源，不覆盖客观事实 |
| A06 | B 从 A 的 E3 分叉，A 已到 E5 | B 看不到 E4/E5，也不使用覆盖 E1..E5 的混合摘要 |
| A07 | 多级分叉与祖先继续推进 | 每层祖先的截止位置生效，无记忆或插件状态串线 |
| A08 | 聊天切小说再切回 | 角色、关系和分支事实不丢失，作者指令不变成角色台词 |
| A09 | 表现层隐藏动作 | 动作仍存在于叙事状态；其他角色是否感知仍按观察条件判断 |
| A10 | 严格控制模式 | 不代写用户动作、台词或内心；需要用户决定时停止 |
| A11 | 第三个 Beat 生成到一半时取消 | 前两个作为 Turn 临时前缀保留，第三个为草稿；未解决前不得开启下一 Turn |
| A12 | 失败请求重试 | 新建请求 Attempt，不重复提交前面已接受的 Beat 或已完成 Turn |
| A13 | 重做已提交 Turn 内的第一条角色输出 | 从该 Turn 之前的检查点生成替代历史，旧输出的后续记忆不进入新分支 |
| A14 | 用户生成中修改角色状态 | 旧执行停止或版本提交失败，不覆盖用户修改 |
| A15 | 摘要任务完成前，源事件被修正 | 旧摘要不能成为有效记忆，任务可重建或作废 |
| A16 | 重复提交同一 Turn / 取消后迟到响应 | 无重复事件、记忆、媒体任务或越过取消的提交 |
| A17 | Actor 已完成而 Chronicler 暂时失败 | Turn 保留临时输出并标记待整理；不提交正式事实或角色记忆，后续 Turn 不启动 |
| A18 | 插件替换 Director | 不修改核心源码；仍遵守知识、预算、版本与取消约束 |
| A19 | 所需插件缺失或返回非法 mutation | 暂停或拒绝该变更，错误可见，历史不损坏 |
| A20 | 导入含未知扩展的卡片、世界书或预设 | 源数据保留，兼容缺口可见，导出不无提示丢字段 |
| A21 | 从 E3 回放历史 | 不重新执行模型调用、付费生图或外部工具 |
| A22 | 聊天历史生成小说改写 Artifact | 不静默改写已确认事实；新增剧情需明确采纳 |
| A23 | 同一用户切换两套人设发送消息 | 每条消息保留实际人设归属；两套人设的关系、物品和知识不混合 |
| A24 | 用户以 OOC 修改故事后继续扮演某人设 | 用户可编辑全局状态，但系统替该人设生成时仅使用该人设可知事实 |
| A25 | 用户选择尚未在场的人设作为发送者 | 要求选择登场、接管或新分支语义，不自动改写场景内身份 |
| A26 | 一个 Turn 同时包含角色输入和作者指令 | 两者作为同一 Turn 提交；作者指令不变成角色台词 |
| A27 | 作者指令包含多行要求 | 保留一个作者输入事件，不自动伪造多条独立 Turn |
| A28 | 用户只填写作者指令 | 可以执行作者操控流程，不要求伪造用户角色发言 |
| A29 | 用户临时接管 Bob 后切换输入角色 | Bob 仍保持用户控制；只有显式交还才恢复 Agent 控制 |
| A30 | 作者要求“下一步让 Alice 质问 Bob” | 作为强制下一步进入 Plan，不提前写成已发生事件，也不能被 Director 静默忽略 |
| A31 | 用户拒绝新角色在当前 Turn 登场 | 当前 Turn 后续 Plan 不安排该角色；下一 Turn 可以重新提议，不自动生成 Scene/Branch 永久禁令 |
| A32 | Turn 生成第 10 个 Beat | Turn 停止并发送 `turn.needs_continue`；不自动生成第 11 个 Beat，用户点击继续后创建新 Turn |
| A33 | Chronicler 或摘要生成失败 | 当前 Turn 不提交事件、状态、记忆或 Branch head；保留临时 Attempt 供恢复 |
| A34 | Actor 使用向量检索 | 先按 Branch、角色权限和来源有效性过滤，再执行向量检索和 Archivist 整理 |
| A35 | 账号密码登录与 WebSocket 重连 | 未鉴权的 HTTP 和 WebSocket 请求被拒绝；有效会话可以恢复当前工作区 |
| A36 | 正则后处理与第三方 UI 扩展 | 声明式正则规则可以执行；原酒馆 UI 脚本不能原样执行，必须通过本系统 UI Extension API 适配 |

## 3. 运行和部署验收

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| R01 | 容器重启或应用升级 | `$APP_DATA_DIR` 中的数据库、媒体、插件和已提交事件完整保留 |
| R02 | 两个 app 实例挂载同一数据目录 | 启动检查拒绝该拓扑；不支持共享 SQLite 或多副本写入 |
| R03 | 后端插件进程崩溃 | 当前插件执行失败并记录，主服务、SQLite 和其他插件不被连带终止 |
| R04 | 服务启动时迁移失败 | 服务拒绝接受 Turn，避免以未知 schema 写入事件 |
| R05 | 运行中执行应用备份 | 备份包含一致的 SQLite 状态，不遗漏 WAL 中已提交内容 |
| R06 | ContextSnapshot 达到 300 MB 配额 | 不自动删除旧快照；新快照保存失败并提示用户手动清理 |
| R07 | 用户启用局域网监听 | 服务可以监听配置指定地址，但 HTTP 和 WebSocket 仍要求单用户会话鉴权 |

## 4. 测试要求

- 单元测试使用确定性模拟 Provider，覆盖事件提交、角色知识过滤、分支可达性、Turn 中断恢复和幂等提交。
- 真实模型测试重点观察知识泄漏、角色一致性、结构化结果失败率、首条回复延迟、总请求数和费用。
- 模型输出测试不能替代事件、分支、角色知识和提交边界的数据隔离测试。
- 页面、HTTP/WebSocket 和断线恢复验收分别引用配套规格中的前端和接口场景。
