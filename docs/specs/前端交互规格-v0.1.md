# 前端交互规格

- 版本：0.1
- 日期：2026-09-23
- 状态：MVP 交互规格。
- 依赖：[叙事运行时规格](./叙事运行时规格-v0.1.md)、[接口契约规格](./接口契约规格-v0.1.md)。
- 范围：Vue 页面、输入、展示、移动端、运行状态和用户操作。
- 非范围：故事事实如何推导、角色知识过滤、分支记忆、HTTP payload 细节。

## 1. 产品原则

1. 页面展示故事，运行时决定故事是否已经正式发生。
2. 用户可以在同一个 Turn 中作为角色发言，并附加一份作者指令。
3. 作者指令是可选文本块，不是第二个默认常驻输入框。
4. 用户可查看并修改状态，但“查看秘密”不改变角色是否知道秘密。
5. 手机端优先保证输入、停止生成和切换操控角色可用；复杂信息进入可展开面板。

## 2. 技术边界

前端使用 Vue 3、TypeScript、Vite、Vue Router、Pinia 和 TanStack Vue Query。

- Pinia 保存纯 UI 状态：当前 Story/Branch/Scene、打开的面板、输入草稿、临时筛选和本地展示偏好。
- Vue Query 保存 API 获取的快照及其失效状态。
- Runtime Event 是服务端真相；正式 `turn.committed` 后才更新已提交故事视图。`beat.accepted` 只显示为当前 Turn 的临时输出。
- 浏览器不直连模型供应商，不保存模型 API Key，也不生成故事状态 mutation 的最终版本。

开发环境运行 Vite 和 Fastify 两个进程，Vite 将 API 与 WebSocket 代理到后端。生产构建后，Vue 静态文件由同一个 Fastify 应用实例提供：`pnpm start` 只启动一个 Node 服务，同时提供页面、API、WebSocket 和 Runtime。Docker Compose 只要求一个 `app` 服务及其持久化数据卷；反向代理是可选组件。

## 3. MVP 页面

| 页面 | 目标 | 必须内容 |
| --- | --- | --- |
| 故事列表 | 打开、创建、管理 Story | Story 名称、最后活动时间、默认 Branch |
| 故事工作区 | 阅读和推进当前 Branch | 会话流、输入区、模式、停止、侧栏入口 |
| 资源与角色 | 管理角色卡、世界书、用户人设、角色操控 | 导入、版本、绑定到 Story、当前操控者 |
| 分支与历史 | 查看检查点和创建分支 | 当前 head、分叉点、切换 Branch |
| 状态面板 | 查看与编辑场景、关系、知识、插件状态 | 来源、作用域、修改入口 |
| 设置 | 管理模型连接、显示偏好、插件与数据目录信息 | 密钥掩码、连接测试、插件版本/权限 |

MVP 不做营销首页。打开应用后的主要界面是故事列表或最近 Story 工作区。

## 4. 故事工作区

### 4.1 桌面布局

```text
┌──────────┬──────────────────────────────┬─────────────┐
│ Story    │ 当前 Scene / 会话流           │ 场景与状态   │
│ Branch   │ 已提交消息、草稿、旁白、媒体   │ 角色/关系    │
│ 角色     │                              │ 分支/插件    │
├──────────┴──────────────────────────────┴─────────────┤
│ 当前操控角色 [选择]  模式 [聊天/小说]  权限 [选择]      │
│ 角色输入                                                    │
│ 作者指令（可选）                                            │
│ [停止]                                           [发送]     │
└────────────────────────────────────────────────────────────┘
```

- 左栏用于 Story、Branch、Scene 和角色上下文切换；可折叠。
- 中栏是唯一的主要阅读区域，按故事顺序显示 Artifact 和执行状态。
- 右栏是可折叠的状态检查器，不将每个区域都做成浮动卡片。
- 输入区固定在阅读区域底部，但不得遮挡未读内容或移动端键盘。

### 4.2 移动端布局

移动端默认只有会话流和底部输入区。Story、角色、状态和分支从侧边抽屉或底部面板进入；不要常驻双栏。

- 当前操控角色、模式和剧情权限采用紧凑的顶部栏或输入区上方一行。
- 停止生成必须始终可见，不能藏在二级菜单。
- 发送按钮仅在有可提交输入时可用；只填写作者指令也可提交。
- 当前 Turn 达到 10 个 Beat 后显示“继续”操作；点击后创建新的 Turn，不自动静默生成第 11 个 Beat。
- 侧栏打开时不停止正在运行的 Turn；用户点击停止才触发取消。

## 5. 复合 Turn 输入

### 5.1 基本规则

MVP 画面一次编辑一个故事内角色输入，归属为当前操控角色。底层接口保留多个 `actorInputs` 的能力，但“在一个表单中组合多个用户角色发言”不属于 v0.1 UI。

用户可以将当前操控角色切换为自己的任意用户人设，或暂时接管一个 NPC。切换仅改变下一次输入的归属，不自动让该角色在故事中登场、离场或获得新知识。

若选择未在场的人设或 NPC，发送前必须出现明确选择：

- 作为新角色登场。
- 接管当前在场的同一角色实例。
- 从检查点创建新分支后改写。

前端不自行猜测“用户想让谁说话”。

### 5.2 主输入框

主输入框永远代表故事内角色台词或行动，placeholder 随当前操控角色变化，例如“以侦探身份说话或行动”。

- 空的主输入框加空的作者指令不能发送。
- 输入可标识为台词、行动或混合内容，但 MVP 不强制用户手工选类型；服务端会以故事输入处理。
- 用户输入 OOC 或直接状态修改必须从明确入口进入，不能依靠在主输入框里加前缀猜测。
- 输入草稿按 `storyId + branchId + actorId` 本地保存；切换 Branch 或角色后不得把草稿投递到错误对象。

### 5.3 作者指令区

作者指令区是主输入的可选附加区域。一个 Turn 最多一份作者指令文本块；文本中可用多行表达多个要求。

空状态：显示 `添加作者指令` 操作，不常驻第二个大输入框。

填写后：主输入框下直接展示作者指令实际内容预览，不显示“已添加 1 条作者指令”这样的计数替代文本。

- 桌面端展开后，作者指令编辑区位于主输入框下方。
- 移动端预览显示最多三行；超过时省略，并显示“展开编辑”。
- 点击预览或“展开编辑”打开底部编辑面板，面板中可编辑完整文本、清空文本、选择时机、作用域和可见性。
- 清空后回到 `添加作者指令` 状态。
- 作者指令与角色输入共用一个发送按钮和一个 Turn；点击编辑区不会单独执行剧情。

作者指令选项采用渐进展开，默认值为：

| 选项 | 默认值 | 可选值 |
| --- | --- | --- |
| 时机 | `after` | `before`、`after` |
| 作用域 | `turn` | `turn`、`scene`、`branch` |
| 可见性 | `hidden` | `hidden`、`narrator`、`actors` |

`before` 和 `after` 的实际运行语义由《叙事运行时规格》定义。前端不得提供 `inline` 或 `story` 选项。

当可见性选择 `actors` 时，必须继续选择至少一个角色；不得默认选择所有角色。`narrator` 表示通过故事中的旁白/事件体现，不等于所有角色自动知道。

### 5.4 角色操控

“当前操控角色”菜单按以下组展示：

1. 我的用户人设。
2. 当前 Scene 在场的 NPC。
3. 其他 Story 角色。

用户选中尚未接管的 NPC 后，先显示接管确认；成功后界面显示“临时接管”状态。直到用户显式执行“交还控制”，系统不应让该 NPC 的 Actor 自动生成行为。切换当前输入角色不会自动交还此前接管的 NPC；界面需要在角色菜单中持续标识所有仍由用户控制的角色。交还后，NPC 从下一次 Runtime 规划开始重新由 Actor 控制。

用户可以通过状态面板直接改角色关系、物品、位置和知识；这与“临时接管”不同。状态编辑须显示其来源、当前 Branch 和影响范围，提交前要求用户确认。

## 6. 会话流与展示

### 6.1 内容类型

会话流按 Artifact 渲染，至少区分：

- 角色台词。
- 角色动作。
- 情绪或内心内容。
- 旁白。
- 小说正文。
- 图片/媒体。
- 用户作者指令和用户状态修正的可审计记录。

默认不在会话流中展示给角色的隐藏作者指令正文。用户可以从 Turn 详情或审计视图查看它，防止影响角色扮演阅读体验。

### 6.2 展示预设

UI 提供以下组合，不改变 Runtime 事实：

| 预设 | 台词 | 动作/情绪 | 布局 |
| --- | --- | --- | --- |
| 纯对话 | 显示 | 隐藏 | 简洁列表 |
| 聊天气泡 | 显示 | 弱化显示 | 角色气泡 |
| 对话加动作 | 显示 | 显示 | 角色气泡 + 动作行 |
| 完整小说叙事 | 按正文显示 | 融入叙事 | 段落/章节 |

隐藏并不删除内容。用户切换预设时仅重新渲染当前 Branch 的已提交 Artifact。

### 6.3 草稿、正式内容与停止

- `draft` 内容需有明确的生成中状态，视觉上与正式消息区别，但不可误导为错误。
- `beat.accepted` 后，前端将该 Beat 标记为当前 Turn 的临时输出；`turn.committed` 后，前端才将整轮内容标记为正式，并以服务端事件为准更新状态。
- 取消后未提交草稿显示“已中断”，提供“继续”“重试”“采纳完整前缀”和“完整回退”入口；可用操作依赖服务端状态。采纳前缀会先完成 Turn 整理，不能直接把残缺 Beat 变成正式事实。
- 已提交内容不能因为用户点击停止而从会话流静默消失。
- 角色连续输出必须按服务端 Beat/Segment 顺序显示，允许 `Bob -> Bob -> Alice -> Bob`。

## 7. 模式、权限和状态操作

### 7.1 模式与权限

工作区提供两个独立控制项：

- 交互模式：沉浸聊天、小说。
- 剧情推进权限：严格控制、允许补全小动作、允许自动推进剧情、完全旁观。

两者不互相重置。切换在下一个 Turn 生效；正在生成时，界面必须提示用户先停止，不能声称立刻改变了运行中的 Plan。

### 7.2 分支与历史

- 分支面板显示 Branch 名称、分叉 Checkpoint、当前 head 和活动 Scene。
- 从历史消息或 Checkpoint 创建分支前，用户必须选择分叉位置。
- 前端不提供“合并分支”入口，直到运行时具备明确的合并语义。
- 切换 Branch 后会话流、状态面板、输入草稿和当前活动 Scene 都必须刷新到该 Branch。

### 7.3 状态面板

状态面板至少能切换：场景、角色关系、事实、角色知识、记忆、插件状态。

每项显示：当前值、来源事件、Branch、最后修改时间、是否派生数据。编辑事实与编辑某角色知道什么必须是两个明确操作。

## 8. 前端验收场景

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| F01 | 手机端未添加作者指令 | 只显示主输入和“添加作者指令”，不常驻两个大输入框 |
| F02 | 手机端作者指令很长 | 预览显示实际内容并截断；展开编辑可查看、修改完整文本 |
| F03 | 一次发送角色输入和作者指令 | 只有一次发送操作，前端提交一个 Turn |
| F04 | 用户只填写作者指令 | 发送可用，不伪造角色发言 |
| F05 | 作者指令为空 | 不提交空对象或空字符串作为作者指令 |
| F06 | 切换用户人设 | 下一条消息归属新 actor，旧草稿不被误发 |
| F07 | 临时接管 Bob | 输入区明确标记临时接管；交还前不显示 Bob 的自动 Actor 生成 |
| F08 | 收到草稿后用户点停止 | 草稿显示已中断，已接受 Beat 显示为 Turn 临时前缀；在 Turn 提交或回退前，不显示为正式事实 |
| F09 | 从聊天切到完整小说叙事 | 只改变呈现，不改写已提交事实 |
| F10 | 用户查看 Alice 的秘密 | 不产生任何角色知识变更请求 |
| F11 | 用户编辑 Bob 的知识 | 操作界面明确区分事实与知识，并显示 Branch 与来源 |
| F12 | WebSocket 重连 | 前端补回正式事件；不把本地草稿伪装成正式故事 |

## 9. 已确定的 v0.1 行为

1. 用户不需要手工选择“台词/行动”类型；主输入统一保存为角色输入，由 Runtime 和 Chronicler 区分事件类型。
2. 小说模式继续使用同一个作者指令编辑面板；章节目标写在作者指令文本中，不新增第二个 Turn 输入框。
3. 移动端状态面板使用底部抽屉，默认顺序为场景、角色、关系、事实、记忆、插件状态；每次只展开一个编辑区域。
4. 角色消息默认显示头像、名称、正文和可选动作；情绪只有在模型返回结构化情绪且展示设置开启时显示；媒体以消息内 Artifact 预览显示。
5. 插件前端只能通过 `UiExtension` 插槽注册，默认关闭任意 HTML/JavaScript 注入；安装和权限状态由设置页管理。
