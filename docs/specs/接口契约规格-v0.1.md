# 接口契约规格

- 版本：0.1
- 日期：2026-09-23
- 状态：MVP 传输契约规格；实现时直接生成 JSON Schema、OpenAPI 与 TypeScript 类型。
- 依赖：[叙事运行时规格](./叙事运行时规格-v0.1.md)、[前端交互规格](./前端交互规格-v0.1.md)、[数据模型规格](./数据模型规格-v0.1.md)。
- 范围：HTTP 命令、查询、WebSocket 事件、幂等、错误和重连。
- 非范围：数据库表结构、页面行为、Director/Actor/Chronicler 的内部 prompt 和实现。

## 1. 基本规则

1. 所有 API 路径以 `/api/v1` 开头；事件通道为 `/ws/runtime`。
2. HTTP 命令创建或修改领域状态；WebSocket 下行推送 Runtime Event，上行只接受订阅、取消订阅、确认和心跳控制帧，不接受创建 Turn、修改状态等业务写命令。
3. API payload 使用 JSON，字段名使用 `camelCase`，ID 使用不透明字符串。
4. 所有响应与事件携带 `schemaVersion`；v0.1 固定为 `"1"`。
5. 浏览器不直连 DeepSeek 或任何模型 Provider。上游流式协议只在后端 Vercel AI SDK Provider 内部存在。
6. MVP 只有一个本地账号。HTTP API 和 WebSocket 都必须鉴权；不实现多用户 Story 隔离。

## 2. 通用格式

### 2.0 鉴权

- 单用户账号名和明文密码只从本机 `.env` 配置文件读取；MVP 不提供网页首次初始化和交互式改密流程，也不把密码保存到数据库。
- 登录成功后使用 HttpOnly、SameSite Cookie 会话；API 不把密码或长期密钥放进前端持久化状态。
- 所有使用 Cookie 的写请求必须校验 `Origin`；没有 `Origin` 的非浏览器客户端必须提供有效的 `X-Requested-With` 或配置的 CSRF header。只读请求不需要 CSRF header。
- 登录成功、登出、密码配置变更和服务重启都会使旧 Session 失效；Session 不在前端持久化。
- WebSocket 握手必须携带有效会话 Cookie，未鉴权连接直接拒绝。
- 局域网监听可以通过配置文件或启动参数启用，但不改变鉴权要求。

### 2.1 命令请求

所有会改变状态的 HTTP 请求必须带：

```http
Content-Type: application/json
Idempotency-Key: <client-generated-opaque-id>
```

相同调用主体、相同 HTTP 方法、相同路径和相同幂等键在服务端保留期内必须返回同一命令结果，不能重复创建 Turn、Branch、状态修正或媒体任务。请求 body 不一致时，服务端返回 `409 idempotency_conflict`。

### 2.2 成功响应

```ts
interface ApiSuccess<T> {
  schemaVersion: "1";
  data: T;
}
```

创建异步执行时，HTTP 只确认命令已被接受，不承诺 Turn 已完成。正式结果通过查询或 Runtime Event 获得。

### 2.3 错误响应

```ts
interface ApiError {
  schemaVersion: "1";
  error: {
    code: string;
    message: string;
    details?: unknown;
    requestId: string;
  };
}
```

错误码至少包括：

| HTTP | code | 含义 |
| --- | --- | --- |
| 400 | `validation_error` | 请求不符合 schema 或枚举值非法 |
| 404 | `not_found` | Story、Branch、Turn、Checkpoint 或资源不存在 |
| 409 | `idempotency_conflict` | 相同幂等键对应不同命令 |
| 409 | `branch_busy` | Branch 有活动执行租约，当前操作不允许并发 |
| 409 | `state_version_conflict` | mutation 的预期版本已过期 |
| 409 | `plan_invalidated` | 旧执行基于过期状态，无法继续提交 |
| 422 | `directive_conflict` | 一个作者指令文本被解析为无法自动处理的冲突要求 |
| 422 | `unsupported_capability` | 请求需要当前 Provider 或插件不支持的能力 |
| 423 | `branch_locked` | Branch 正在执行迁移、恢复或其他独占维护任务 |
| 500 | `internal_error` | 未分类服务端错误 |

## 3. 共享类型

### 3.1 Turn 输入

```ts
interface CreateTurnRequest {
  branchId: string;
  sceneId: string;
  input: TurnInput;
  executionProfileId?: string;
}

interface TurnInput {
  actorInputs: ActorInput[];
  authorDirective?: AuthorDirectiveInput;
}

interface ActorInput {
  actorId: string;
  content: string;
}

interface AuthorDirectiveInput {
  content: string;
  timing: "before" | "after";
  scope: "turn" | "scene" | "branch";
  visibility: "hidden" | "narrator" | "actors";
  visibleToActorIds?: string[];
}
```

约束：

- `actorInputs` 按数组顺序表示同一 Turn 内的用户故事输入顺序；每项 `actorId` 必须是当前 Story 的用户控制角色或已被用户明确临时接管的角色。
- v0.1 前端最多发送一项 `actorInputs`，但服务端必须能校验和保存多项，以避免以后变更传输模型。
- `actorInputs` 可为空，仅当 `authorDirective` 存在且 `content` 非空时合法。
- `authorDirective` 是单个对象，不是数组。空字符串视为缺省，服务端不得创建空作者指令事件。
- `timing: before` 先应用作者约束再提交故事内输入；`after` 先提交故事内输入再应用约束，随后才由 Director 规划生成内容。
- `scope: turn` 在当前 Turn 完成或中断后失效；`scene` 在当前 Scene 结束或被用户撤销后失效；`branch` 在当前 Branch 中持续到被撤销、被后续指令明确替代或 Branch 归档。子 Branch 只继承分叉点之前仍有效的指令。不存在 `inline` 或 `story` 值。
- `visibility: actors` 时 `visibleToActorIds` 必须包含至少一个当前 Story 的角色 ID；其他可见性下该字段必须缺省。服务端不得将 `actors` 解释为广播给所有角色。

### 3.2 创建 Turn 的响应

```ts
interface CreateTurnResponse {
  turnId: string;
  attemptId: string;
  status: "queued" | "running";
  acceptedAt: string;
}
```

`turnId` 是逻辑用户回合身份；`attemptId` 是本次运行尝试身份。重试可产生新的 `attemptId`，不应静默覆盖旧 Attempt。

### 3.3 状态修正

```ts
interface CreateStateMutationRequest {
  branchId: string;
  mutations: StateMutationInput[];
}

interface StateMutationInput {
  namespace: string;
  targetId: string;
  operation: string;
  payload: unknown;
  expectedStateVersion: number;
  intent: "fact" | "knowledge" | "relationship" | "scene" | "plugin";
}
```

用户事实编辑和角色知识编辑必须使用不同的 `intent`。服务端从调用上下文确定写权限、Branch 和来源事件，不信任 body 中任何自称的权限信息。

### 3.4 角色控制状态

```ts
interface SetActorControlRequest {
  controller: "user" | "agent";
  expectedControlVersion: number;
}

interface ActorControlState {
  branchId: string;
  actorId: string;
  controller: "user" | "agent";
  controlVersion: number;
}
```

角色控制状态按 Branch 保存。`controller: user` 表示 Director 不得为该角色生成自动 Beat；`controller: agent` 表示可按运行时剧情权限生成。它不是角色状态 mutation，也不改变角色知识、位置或关系。

### 3.5 重试请求

```ts
type RetryTurnRequest =
  | {
      mode: "retry_request";
      failedRequestAttemptId: string;
    }
  | {
      mode: "continue_draft";
      draftId: string;
    }
  | {
      mode: "resume_from_head";
      previousAttemptId: string;
    }
  | {
      mode: "redo_turn";
      baseCheckpointId: string;
      newBranchName?: string;
    };

interface RetryTurnResponse extends CreateTurnResponse {
  branchId: string;
  createdBranch: boolean;
}
```

`retry_request` 只重试指定失败模型请求，并复用其不可变输入快照；`continue_draft` 发起新的续写请求；`resume_from_head` 保留已提交前缀并重新规划；`redo_turn` 必须从基准 Checkpoint 创建替代 Branch。

## 4. HTTP 命令

| 方法与路径 | 请求 | 响应 | 语义 |
| --- | --- | --- | --- |
| `POST /api/v1/auth/login` | `{ username, password }` | `{ authenticated: true }` | 创建单用户会话 |
| `POST /api/v1/auth/logout` | `{}` | `{ authenticated: false }` | 撤销当前会话 |
| `GET /api/v1/auth/session` | 无 | `{ authenticated, username? }` | 查询当前会话 |
| `POST /api/v1/turns` | `CreateTurnRequest` | `CreateTurnResponse` | 创建 Turn 并取得 Branch 执行租约 |
| `POST /api/v1/turns/{turnId}/cancel` | `{ attemptId }` | `{ turnId, attemptId, status }` | 请求取消指定运行 Attempt |
| `POST /api/v1/turns/{turnId}/rollback` | `{ attemptId }` | `{ turnId, branchHead, status: "rolled_back" }` | 放弃当前 Turn 临时输出，恢复到 Turn 开始前的 Branch head |
| `POST /api/v1/turns/{turnId}/retry` | `RetryTurnRequest` | `RetryTurnResponse` | 按明确粒度创建新 Attempt；`redo_turn` 创建替代 Branch |
| `POST /api/v1/branches/{branchId}/fork` | `{ checkpointId, name? }` | `{ branchId, baseCheckpointId }` | 从检查点创建新 Branch |
| `POST /api/v1/state/mutations` | `CreateStateMutationRequest` | `{ committedEventIds, branchHead }` | 提交用户明确发起的状态修正 |
| `PUT /api/v1/branches/{branchId}/actor-controls/{actorId}` | `SetActorControlRequest` | `ActorControlState` | 接管或交还某个角色；版本冲突返回 `state_version_conflict` |
| `POST /api/v1/drafts/{draftId}/adopt` | `{ mode: "as_is" }` | `{ committedTurnId }` | 用户明确将一个完整 Turn 前缀采纳为正式内容；仍需运行时校验、Chronicler 整理和角色记忆提取 |

取消接口只确认“已接收取消请求”。最终状态由 `turn.interrupted`、`turn.completed` 或 `turn.failed` 事件确认。

`redo_turn` 及重做已提交 Turn 内 Beat 的实现必须创建替代 Branch，不能原地篡改已提交历史。v0.1 可以通过 Branch fork 加新 Turn 实现重做，不要求为单个 Beat 提供独立 endpoint；无论接口如何拆分，都必须遵守同一分支和审计语义。

## 5. HTTP 查询

| 方法与路径 | 响应核心字段 | 语义 |
| --- | --- | --- |
| `GET /api/v1/stories` | Story 摘要数组 | 故事列表 |
| `GET /api/v1/stories/{storyId}` | Story、资源绑定、默认 Branch | 打开 Story 元信息 |
| `GET /api/v1/branches/{branchId}/snapshot` | `branchHead`、`stateProjection`、`projectionWatermark` | 读取当前 Branch 状态快照 |
| `GET /api/v1/branches/{branchId}/events` | 事件分页、序列范围 | 回放与断线补拉正式事件 |
| `GET /api/v1/scenes/{sceneId}` | Scene、在场者、活动状态 | 场景详情 |
| `GET /api/v1/turns/{turnId}` | Turn、Attempts、草稿/提交状态 | 恢复、重试与审计 |
| `GET /api/v1/characters/{actorId}/state` | 角色可编辑状态与来源 | 状态面板 |
| `GET /api/v1/branches/{branchId}/actor-controls` | `ActorControlState[]` | 当前 Branch 的角色控制状态 |
| `GET /api/v1/plugins` | Manifest、版本、状态、权限 | 插件管理 |

事件查询必须支持 `afterSequence` 和 `limit`。仅返回当前单用户账号可访问的 Story/Branch 事件；单用户部署的访问控制简化不等于省略数据边界。

## 6. WebSocket Runtime Event

### 6.1 连接与订阅

客户端连接 `WS /ws/runtime` 后先发送订阅帧：

```ts
interface SubscribeFrame {
  type: "subscribe";
  schemaVersion: "1";
  branchId: string;
  afterSequence?: number;
}

interface UnsubscribeFrame {
  type: "unsubscribe";
  schemaVersion: "1";
  branchId: string;
}

interface AckFrame {
  type: "ack";
  schemaVersion: "1";
  branchId: string;
  sequence: number;
}

interface PingFrame {
  type: "ping";
  schemaVersion: "1";
  nonce: string;
}
```

服务端在验证 Branch 后发送：

```ts
interface SubscribedFrame {
  type: "subscribed";
  schemaVersion: "1";
  branchId: string;
  replayFromSequence: number;
}
```

`afterSequence` 为排他游标：服务端只重放 `sequence > afterSequence` 的持久化事件。`ack` 只表示客户端已处理到哪个持久化序列，用于诊断和流量控制，不改变故事状态。`ping` 只用于保活，服务端回复相同 nonce 的 `pong`。

单个 WebSocket 连接可以订阅多个 Branch，但每个 Branch 的序列独立递增。客户端切换 Branch 后可以保留旧订阅或显式取消订阅；前端默认只订阅当前工作区 Branch。

### 6.2 通用事件信封

```ts
interface RuntimeEvent<T = unknown> {
  type: string;
  schemaVersion: "1";
  eventId: string;
  branchId: string;
  sequence?: number;
  occurredAt: string;
  turnId?: string;
  attemptId?: string;
  payload: T;
}
```

- `sequence` 只分配给会改变 Branch 正式历史的持久化事件，并在同一 Branch 内严格递增；有 `sequence` 的事件可通过 `GET /events?afterSequence=` 补拉，不能重排。执行审计和 Turn 临时事件可以持久化，但不占用 Branch `sequence`，通过 Turn 详情查询。
- `beat.draft.delta` 是瞬时事件，不携带 Branch `sequence`。其 payload 必须含 `draftId` 和单调递增的 `draftRevision`；服务端可以压缩旧 delta。
- 客户端发现 `draftRevision` 缺口时请求或等待最新草稿快照，不能自行猜测缺失文本。
- WebSocket 不是唯一事件存储；断线恢复以持久化事件和草稿快照为准。

### 6.3 必需事件类型

| type | 是否正式叙事 | payload 要点 |
| --- | --- | --- |
| `turn.started` | 否 | Turn、Attempt、执行快照引用 |
| `plan.created` | 否 | Plan ID、参与者、计划摘要；不向错误 Actor 泄露完整计划 |
| `beat.draft.started` | 否 | Beat、Actor、Draft ID |
| `beat.draft.delta` | 否 | Draft ID、追加文本或替换快照 |
| `beat.draft.completed` | 否 | Draft ID、候选完成状态 |
| `beat.accepted` | 否 | Turn 内已接受的 Beat、临时 Segment、临时状态版本；不推进 Branch head |
| `turn.committed` | 是 | Turn 的正式 Segment、事件 ID、角色记忆变更、Branch head |
| `state.committed` | 是 | mutation 结果、来源事件、投影水位 |
| `turn.interrupted` | 否 | 取消原因、已接受的临时前缀、未完成 Draft、可用恢复动作 |
| `turn.needs_continue` | 否 | 达到 Turn 的 Beat 上限、当前分支位置、继续操作所需的基准 Checkpoint |
| `turn.failed` | 否 | 可安全显示的错误码、失败阶段、是否可重试 |
| `turn.completed` | 否 | 最终 Branch head、下一步状态 |
| `plugin.failed` | 否 | 插件 ID、阶段、可安全显示的失败信息 |

`beat.accepted` 只表示 Turn 内临时输出已被后续 Beat 使用，客户端不得将其显示为已提交事实。`turn.committed` 才表示事件、公共状态和角色记忆已经正式生效。客户端不依据 `plan.created` 或 `beat.draft.completed` 判断某剧情已发生。

除 `beat.draft.delta` 外，上表事件都必须持久化；只有会改变 Branch 正式历史的 `turn.committed`、`state.committed` 和用户事实修正事件携带 Branch `sequence`。`beat.draft.delta` 的 payload 使用 `{ draftId, draftRevision, mode, text }`，其中 `mode` 为 `append` 或 `replace`。

## 7. 断线、取消与恢复

- 浏览器断线不取消 Turn；只有 `POST /cancel` 或服务端维护策略才可取消。
- 重连时客户端以最后成功处理的正式 `sequence` 订阅；服务端先补正式事件，再开始实时推送。
- 如草稿仍存在，服务端发送最新草稿快照；如草稿已丢弃，发送 `turn.interrupted` 或对应状态，客户端不得继续显示旧草稿为当前生成内容。
- 取消与 Turn 提交竞争时，以服务端提交闸门写入的正式事件为准。客户端收到最后一个 token 不代表 Beat 或 Turn 已提交。

## 8. OpenAPI 与 Schema 交付

- HTTP request/response 使用 JSON Schema 作为唯一规范来源，并生成 OpenAPI 文档与 TypeScript 类型。
- WebSocket frame 和 Runtime Event 使用同一 `packages/contracts` 中的版本化 JSON Schema。
- 前端、后端和插件 SDK 均不得各自手写一份漂移的类型定义。
- 任意破坏性变更必须升级 API/事件 schema 版本，或通过兼容字段演进；不能复用字段名偷偷改变含义。

## 9. 接口验收场景

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| I01 | `POST /turns` 含角色输入和作者指令 | 返回一个 Turn/Attempt；作者指令为单个对象 |
| I02 | `POST /turns` 只有作者指令 | 接受请求，不生成伪造 ActorInput |
| I03 | 作者指令含 `inline` 或 `story` | 返回 `validation_error` |
| I04 | 相同命令重复使用相同幂等键 | 返回原命令结果，不重复创建 Turn |
| I05 | 相同幂等键对应不同 body | 返回 `idempotency_conflict` |
| I06 | `beat.draft.delta` 后连接断开 | 重连后补正式事件，并获取当前草稿快照或中断状态 |
| I07 | Turn 内已接受 Beat 后收到取消 | `beat.accepted` 只保留为临时前缀；后续 Beat 停止，等待继续、采纳或回退 |
| I08 | Turn 提交先通过闸门后收到取消 | `turn.committed` 保留，旧 Attempt 的迟到响应不能再提交新的 Turn |
| I09 | UI 只收到 `plan.created` | 不将该 Plan 当作正式剧情 |
| I10 | 用户编辑事实和角色知识 | mutation 的 `intent` 不同，来源和版本可审计 |
| I11 | 从 Checkpoint 创建分支 | 响应包含新 Branch 和基准 Checkpoint，不修改父 Branch head |
| I12 | 请求未知或失效资源 | 返回统一 `not_found` 或 `state_version_conflict` 错误信封 |
| I13 | 接管 Bob 后旧 Plan 尝试提交 | 控制版本变化使旧 Plan 失败为 `plan_invalidated`，Bob 不产生自动 Beat |
| I14 | 仅切换前端当前输入角色 | 不发送角色控制更新；此前接管的 NPC 控制状态保持不变 |

## 10. 已确定的实现边界

1. 资源、角色卡、世界书、模型连接和插件安装的完整 CRUD 路径属于实现阶段的普通资源接口，必须遵守本文通用鉴权、幂等和版本规则。
2. 媒体上传、下载、范围请求和异步任务接口属于 Artifact/Job 资源接口，不能绕过 Artifact 来源和 Branch 约束。
3. retry mode 固定为：请求级重试、残缺草稿续写、当前 Turn 继续、从检查点重做；语义见《叙事运行时规格》，不再增加隐式重试模式。
4. 插件 RPC 的公共输入输出 schema 与 HTTP/WebSocket 契约共同放在版本化 `packages/contracts`；PluginHost 内部控制帧可以使用独立私有 schema。
