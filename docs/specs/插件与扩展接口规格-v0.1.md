# 插件与扩展接口规格

- 版本：0.1
- 日期：2026-09-23
- 状态：v0.1 插件接口规格
- 范围：后端插件 Manifest、能力注册、Host RPC、三类 Agent 替换、状态扩展、正则后处理和 UI 扩展。
- 运行模型：自托管 Node 插件；插件是可信服务器代码，进程隔离用于稳定性和资源管理，不是恶意代码安全沙箱。

## 1. 设计原则

1. 插件可以替换和增强能力，但不能绕过 Runtime 的知识过滤、Branch 隔离、Turn 提交和权限检查。
2. 插件通过 Host API 工作，不直接访问 SQLite、Fastify、模型密钥或内部对象。
3. 插件输出必须是带 schema 版本的提案，由 Runtime 校验后提交。
4. 用户必须显式选择角色槽位或工作流插件，插件不能凭优先级静默接管。
5. 插件状态绑定 Story/Branch/Checkpoint，禁止使用全局缓存串线。

## 2. Manifest

```ts
interface PluginManifest {
  id: string;
  version: string;
  displayName: string;
  hostApiVersion: string;
  entry: string;
  capabilities: string[];
  permissions: string[];
  dependencies: Array<{ id: string; versionRange: string }>;
  configSchema?: JsonSchema;
  stateSchema?: JsonSchema;
  migrations?: string[];
}
```

能力示例：

- `role.director`
- `role.actor`
- `role.chronicler`
- `context.provider`
- `memory.provider`
- `retrieval.provider`
- `tool.provider`
- `media.provider`
- `ui.panel`
- `ui.input_extension`
- `state.namespace`
- `postprocess.regex`

权限示例：

- `state:read`
- `state:write`
- `memory:read`
- `authorDirective:read`
- `model:call`
- `tool:call`
- `network`
- `filesystem:read`
- `filesystem:write`
- `ui:register`

Manifest 声明的权限必须显示给用户并记录到安装和执行日志。权限只能缩小 Host API 能力，不能扩大 Runtime 已经绑定的角色范围。

## 3. 生命周期

```text
installed -> enabled -> running -> stopped
                         |-> failed
enabled -> disabled
installed -> removed
```

- 安装时校验 Manifest、依赖、API 版本和入口文件。
- 启用时加载配置 schema 和状态 schema。
- 运行时每个插件使用独立 PluginHost Node 子进程。
- 插件崩溃、超时或返回非法结果时，只失败当前插件调用；主 Runtime 保留错误和输入版本。
- 卸载不物理删除插件状态，状态标记为不可用，重新安装相同 ID 后可迁移恢复。
- 升级必须执行声明的迁移；迁移失败时停用插件，不修改已经提交的故事事实。

## 4. Host RPC

Host 至少提供以下语义接口：

```ts
interface ScopedHost {
  readState(query: StateQuery): Promise<StateView>;
  retrieveMemory(query: MemoryQuery): Promise<MemoryHit[]>;
  retrieveDocuments(query: DocumentQuery): Promise<DocumentHit[]>;
  callModel(request: ModelCall): Promise<ModelResult>;
  callTool(request: ToolCall): Promise<ToolResult>;
  emitDraft(event: DraftEvent): Promise<void>;
  proposeState(mutations: StateMutation[]): Promise<ProposalReceipt>;
  registerUiExtension(extension: UiExtension): Promise<RegistrationReceipt>;
  log(entry: PluginLogEntry): Promise<void>;
  getConfig(): Promise<unknown>;
}
```

Host 根据执行身份绑定 Story、Branch、Turn、Actor 和可见材料。插件不能通过传入另一个 `actorId` 扩大读取权限。

插件不能：

- 直接访问数据库或修改 SQLite 文件。
- 读取原始模型密钥。
- 读取未过滤的全库事件、记忆或向量索引。
- 直接提交 `NarrativeEvent`、`ActorMemory` 或 `StateProjection`。
- 修改 `visibility`、Branch 或 Checkpoint 来扩大权限。
- 把 Director 的全知计划、其他角色记忆或隐藏作者指令直接交给 Actor。

## 5. 三类 Agent 插件

```ts
interface RoleProvider<I, O> {
  id: string;
  role: "director" | "actor" | "chronicler";
  apiVersion: string;
  run(input: I, host: ScopedHost, signal: AbortSignal): Promise<O>;
}
```

- Director 插件输出 `ScenePlan`、参与者、Beat 顺序、结束条件和可选 SceneMutation 提案。
- Actor 插件输出一个角色的叙事表现、信号和状态提案，不能直接决定其他角色的秘密。
- Chronicler 插件输出事件、公共状态、角色记忆、TurnSummary 和 StorySummary 提案；所有内容必须带来源范围。

插件仍受 Turn 的 20 次模型请求、Beat 上限、超时、取消和提交事务约束。Chronicler 是 Turn 正式提交的必需阶段，不能被后台任务替代。

## 6. 自定义状态

插件状态使用命名空间保存。推荐结构不是强制业务模型：

```json
{
  "schemaVersion": "1",
  "status": "active",
  "data": {},
  "derived": {},
  "sourceRefs": [],
  "updatedAt": "2026-09-23T00:00:00Z"
}
```

- `data`：插件拥有的正式状态。
- `derived`：可以从正式事件重建的派生结果。
- `sourceRefs`：来源事件、Turn 或 Artifact ID。
- `schemaVersion`：用于迁移和兼容检查。

插件状态必须声明 Story/Branch 作用域。用户可以查看、修改、导出和清理插件状态；修改通过 `proposeState`，不允许插件直接覆盖数据库。

## 7. 正则后处理插件

正则后处理优先使用声明式配置：

```ts
interface RegexRule {
  id: string;
  phase: "beforeModel" | "afterModel" | "beforeDisplay";
  target: "director" | "actor" | "chronicler" | "artifact";
  pattern: string;
  replacement: string;
  flags?: string;
  order: number;
  enabled: boolean;
}
```

规则版本和启用结果写入 ContextSnapshot。规则不能修改正式事实、角色权限或作者指令可见性。需要条件判断、网络访问或复杂逻辑时使用普通后端插件，不把任意 JavaScript 当作正则脚本执行。

## 8. UI 扩展

```ts
interface UiExtension {
  id: string;
  slot:
    | "story.sidebar"
    | "story.inspector"
    | "story.input.before"
    | "story.input.after"
    | "story.turn.actions"
    | "story.artifact.actions"
    | "settings.panel";
  title: string;
  schemaVersion: string;
  propsSchema?: JsonSchema;
  actions: Array<{ id: string; label: string; command: string }>;
}
```

UI 扩展通过本项目前端扩展协议渲染和发送命令，不直接操作 DOM、Pinia 内部对象或 WebSocket 原始业务帧。第三方酒馆 UI 需要改写为本接口。

## 9. 错误和可观测性

每次插件调用记录：插件 ID、版本、能力、权限、Story/Branch/Turn、输入 schema 版本、开始/结束时间、状态、错误码和来源版本。日志不得包含模型密钥。

插件错误至少分为：`plugin_timeout`、`plugin_crashed`、`invalid_output`、`permission_denied`、`dependency_missing`、`schema_mismatch` 和 `migration_failed`。

插件返回非法 mutation 时，Runtime 拒绝该 mutation；已经提交的其他正式数据不回滚，当前 Turn 是否继续由工作流定义，默认暂停并提示用户。

## 10. MVP 验收

- 示例插件可以替换 Director，不修改核心源码。
- 示例插件可以读取自身被授权的状态并提出 JSON 状态 mutation。
- 插件无法读取另一个角色的私有记忆或隐藏作者指令。
- 插件超时不会让主服务进程退出。
- 声明式正则可以导入、排序、重试和审计。
- UI 扩展可以在输入区或状态检查器注册入口，并通过标准命令修改状态。
