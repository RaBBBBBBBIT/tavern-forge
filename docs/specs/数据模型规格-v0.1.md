## 1. 数据分层

系统中的数据分成五层：

```text
资源层
  角色卡、世界书、Preset、用户人设、模型连接

故事层
  Story、Branch、Scene、ActorInstance、控制状态

事实层
  Turn、NarrativeEvent、StateMutation、Checkpoint

认知层
  ActorMemory、Summary、ContextSnapshot

执行层
  TurnAttempt、Beat、ModelRequestAttempt、ToolInvocation、Artifact、RuntimeEvent

系统层
  AuthCredential、AuthSession、IdempotencyKey、BackgroundJob
```

这五层不能混为一个“大 JSON”：

- 资源层描述可复用设定，不保存某条故事线已经发生的结果。
- 故事层描述一次故事及其分支结构。
- 事实层描述已经提交的故事结果，是分支回放和状态重建的依据。
- 认知层描述角色记得什么以及模型调用使用的上下文，是事实层的受约束派生数据。
- 执行层描述系统如何得到结果，不能单独证明剧情已经发生。

## 2. 持久化原则

### 2.0 已确定的三个决策

1. `NarrativeEvent` 和 `StateMutation` 分开保存。前者表示“发生了什么”，后者表示“状态如何变化”；两者可以通过 `sourceEventIds` 关联，但不能混成一个没有明确语义的通用事件 JSON。
2. 采用结构化字段和 JSON 混合模型。Branch、Turn、Scene、Actor、控制状态、事件顺序、状态版本等高频查询字段使用独立列；角色卡扩展、状态 payload、插件数据和模型参数使用 JSON。
3. MVP 默认保存完整 `ContextSnapshot`，包括渲染后的消息、材料来源、版本和裁剪结果。默认总配额为 300 MB，不设置自动过期时间；用户可以手动清理。达到配额后不自动删除旧快照，新的快照保存需要提示用户清理空间。MVP 不对快照加密。

### 2.1 正式数据和临时数据分开

正式数据：

- 已提交的 Turn。
- 已确认的 NarrativeEvent。
- 已接受的状态变更。
- 已生效的角色记忆和摘要版本。
- Branch head 和 Checkpoint。

临时数据：

- 未完成的 TurnAttempt。
- Director Plan。
- 流式草稿。
- 已接受但尚未提交的 Beat。
- 未确认的模型状态提案。
- 待继续、待采纳或待回退的 TurnWorkingState。

临时数据可以持久化，以支持断线恢复，但不能被普通历史查询当成正式剧情，也不能被下一个 Turn 使用。

### 2.2 事实和派生结果分开

`NarrativeEvent` 是正式事实来源。以下内容都是派生结果：

- 当前公共状态。
- 角色个人状态。
- ActorMemory。
- TurnSummary、SceneSummary、ArcSummary 和 StorySummary。
- 全文索引和向量索引。

派生结果必须记录来源事件或处理水位。派生数据损坏时，可以从有效事件和资源版本重新生成。

### 2.3 不删除已经提交的历史

用户修改已经提交的事实、记忆或摘要时，不直接覆盖旧记录：

1. 记录用户的修正操作。
2. 追加修正事件或修正记录。
3. 让依赖旧版本的派生数据失效。
4. 重新生成有效投影。

用户界面可以展示“当前有效版本”，但数据库仍保留旧版本和来源。

## 3. 对象关系总览

```text
UserOperator
  ├─ UserPersonaDefinition -> UserActorInstance
  └─ Story
       ├─ StoryResourceBinding -> AssetRevision
       ├─ Branch
       │    ├─ Scene
       │    ├─ ActorControlAssignment
       │    ├─ Turn -> TurnAttempt -> Beat -> Artifact
       │    ├─ NarrativeEvent -> StateMutation
       │    ├─ ActorMemory
       │    ├─ Summary
       │    └─ Checkpoint
       └─ PluginInstallation / ExecutionProfile
```

Branch 不是复制一份完整 Story。子 Branch 通过父 Branch 和分叉 Checkpoint 访问祖先历史，在分叉点之后只读取自己的记录。

## 4. 资源层

### 4.1 Asset 和 AssetRevision

所有可复用资源都使用“逻辑资源 + 不可变版本”：

```ts
interface Asset {
  id: string;
  kind: "character" | "worldbook" | "preset" | "user_persona" | "other";
  ownerId?: string;
  name: string;
  createdAt: string;
  archivedAt?: string;
}

interface AssetRevision {
  id: string;
  assetId: string;
  revision: number;
  sourceFormat?: string;
  sourcePayload: unknown;
  normalizedPayload?: unknown;
  extensionPayload?: unknown;
  createdAt: string;
}
```

规则：

- 导入酒馆角色卡、世界书和 Preset 时保留原始内容。
- 标准字段进入 `normalizedPayload`，未知字段进入 `extensionPayload`。
- Story 绑定具体 `AssetRevision`，不会自动跟随资源最新版本。
- 修改资源产生新版本，不静默修改已经运行过的故事。

### 4.2 StoryResourceBinding

```ts
interface StoryResourceBinding {
  id: string;
  storyId: string;
  assetRevisionId: string;
  bindingKind: "character" | "worldbook" | "preset" | "other";
  priority?: number;
  enabled: boolean;
  activationConfig?: unknown;
  createdAt: string;
}
```

一个 Story 可以绑定多本 Worldbook。每本书独立保留版本、优先级和激活条件，不能在导入时永久拼成一个文本块。

### 4.3 ModelConnection 和 ExecutionProfile

模型连接和本次运行配置分开：

```ts
interface ModelConnection {
  id: string;
  provider: string;
  displayName: string;
  model: string;
  endpoint?: string;
  secretRef: string;
  config: Record<string, unknown>;
  status: "active" | "disabled";
}

interface ExecutionProfile {
  id: string;
  storyId?: string;
  directorModelConnectionId: string;
  actorModelConnectionId: string;
  chroniclerModelConnectionId: string;
  limits: Record<string, unknown>;
  contextPolicyRevisionId?: string;
  pluginConfig?: unknown;
}
```

API Key 等秘密只存放在 SecretStore 或外部环境中。数据库只能保存 `secretRef`，不能把明文密钥写入 Story、Turn、日志或 ContextSnapshot。

## 5. 故事层

### 5.1 Story

```ts
interface Story {
  id: string;
  ownerId?: string;
  title: string;
  status: "active" | "archived";
  defaultBranchId?: string;
  defaultExecutionProfileId?: string;
  createdAt: string;
  updatedAt: string;
}
```

Story 是一次独立游玩或写作项目。它保存资源绑定、用户角色绑定、分支和运行配置，不直接保存某个 Branch 的当前剧情正文。

### 5.2 Branch

```ts
interface Branch {
  id: string;
  storyId: string;
  parentBranchId?: string;
  forkCheckpointId?: string;
  name: string;
  status: "active" | "archived";
  headSequence: number;
  activeSceneId?: string;
  stateVersion: number;
  createdAt: string;
  updatedAt: string;
}
```

分支规则：

- 根 Branch 没有父 Branch 和分叉 Checkpoint。
- 子 Branch 必须从已提交 Turn 的 Checkpoint 创建。
- 子 Branch 继承分叉点之前的祖先历史和派生状态。
- 子 Branch 的新事件、状态、记忆和插件状态不回写父 Branch。
- 查询子 Branch 时，先读取祖先链直到分叉位置，再读取子 Branch 自己的记录。
- `headSequence` 只表示当前 Branch 的正式历史位置，不包括临时 Beat。

### 5.3 Scene

```ts
interface Scene {
  id: string;
  branchId: string;
  name: string;
  status: "active" | "completed" | "archived";
  storyTime?: string;
  location?: string;
  publicState: unknown;
  startedAtTurnId?: string;
  endedAtTurnId?: string;
}
```

Scene 是 Branch 内的叙事组织单位。Director 可以提出创建、结束或切换 Scene 的 `SceneMutation`，但必须由 Runtime 校验 Branch、状态版本、参与者和权限后提交；模型不能直接写 Scene。换地点不自动创建新 Scene；Scene 的公共状态只保存当前场景需要的最小信息，角色私有状态和记忆不塞进 `publicState`。

### 5.4 ActorDefinition 和 ActorInstance

```ts
interface ActorDefinition {
  id: string;
  characterAssetRevisionId?: string;
  name: string;
  profile: unknown;
}

interface ActorInstance {
  id: string;
  storyId: string;
  actorDefinitionId: string;
  kind: "npc" | "user_persona" | "system";
  createdAt: string;
}
```

`ActorDefinition` 描述角色身份，`ActorInstance` 表示该角色参加某个 Story。角色在不同 Story 中的关系、物品、记忆和状态不共享。

### 5.5 用户人设和控制状态

```ts
interface UserPersonaDefinition {
  id: string;
  assetRevisionId: string;
  ownerId?: string;
  name: string;
}

interface UserActorInstance {
  actorInstanceId: string;
  personaRevisionId: string;
  controllerId?: string;
}

interface ActorControlAssignment {
  branchId: string;
  actorId: string;
  controller: "user" | "agent";
  controlVersion: number;
  updatedAt: string;
}
```

控制状态按 Branch 保存。它不是故事事实，也不是角色记忆，但必须有版本，以便接管角色时使旧 Plan 失效。

## 6. 事实层

### 6.1 Turn

```ts
interface Turn {
  id: string;
  storyId: string;
  branchId: string;
  baseCheckpointId: string;
  inputPayload: unknown;
  status: "running" | "interrupted" | "awaiting_resolution" | "needs_continue" | "committed" | "failed" | "rolled_back";
  committedSequenceStart?: number;
  committedSequenceEnd?: number;
  createdAt: string;
  committedAt?: string;
}
```

Turn 是用户输入或显式继续命令对应的逻辑回合，也是正式提交的最小单位。

- 一个 Turn 可以包含一个或多个 TurnAttempt。
- 一个 Turn 可以有多个 Beat。
- Turn 正式提交后才推进 Branch head。
- Turn 输入必须保存实际角色归属和作者指令，不能依赖之后变化的 UI 状态。

### 6.2 TurnAttempt

```ts
interface TurnAttempt {
  id: string;
  turnId: string;
  attemptNumber: number;
  executionProfileSnapshot: unknown;
  pluginVersionSnapshot: unknown;
  baseStateVersion: number;
  status: "queued" | "running" | "completing" | "completed" | "interrupted" | "failed";
  failureCode?: string;
  startedAt?: string;
  endedAt?: string;
}
```

Attempt 保存这次执行实际使用的配置快照。重试可以创建新的 Attempt，但不能让旧 Attempt 的输出重新提交到新的 Branch head。

### 6.3 Beat 和 NarrativeSegment

```ts
interface Beat {
  id: string;
  turnAttemptId: string;
  ordinal: number;
  actorId: string;
  status: "planned" | "generating" | "accepted" | "incomplete" | "failed" | "discarded";
  planId?: string;
  temporaryStateVersion?: number;
}

interface NarrativeSegment {
  id: string;
  beatId: string;
  ordinal: number;
  kind: "dialogue" | "action" | "emotion" | "inner_state" | "narration";
  performerId?: string;
  text: string;
  observerActorIds: string[];
  completeness: "complete" | "incomplete";
}
```

Beat 和 Segment 是执行与展示单位。它们在 Turn 未提交时可以被当前 Turn 的后续 Beat 使用，但不能作为跨 Turn 正式历史。

### 6.4 NarrativeEvent

```ts
interface NarrativeEvent {
  id: string;
  storyId: string;
  branchId: string;
  turnId: string;
  sequence: number;
  kind: "utterance" | "action" | "observation" | "state_correction" | "rule_correction";
  actorId?: string;
  payload: unknown;
  sourceEventIds: string[];
  sourceSegmentIds?: string[];
  createdAt: string;
}
```

规则：

- 只有正式提交的内容才进入 `NarrativeEvent`。
- `sequence` 在 Branch 内严格递增。
- 事件不可通过摘要更新而改变。
- 用户修正事实时追加修正事件，不直接修改旧事件。
- 一个事件可以产生公共状态，也可以产生多个不同角色的记忆。
- 事件不自动等于所有角色都知道；角色认知由记忆和观察结果表达。

### 6.5 StateMutation 和 StateProjection

```ts
interface StateMutation {
  id: string;
  branchId: string;
  turnId?: string;
  namespace: string;
  targetType: string;
  targetId: string;
  operation: string;
  payload: unknown;
  intent: "fact" | "knowledge" | "relationship" | "scene" | "plugin";
  sourceEventIds: string[];
  expectedStateVersion: number;
  status: "proposed" | "accepted" | "rejected" | "superseded";
}

interface StateProjection {
  branchId: string;
  namespace: string;
  targetType: string;
  targetId: string;
  state: unknown;
  version: number;
  processedThroughSequence: number;
  updatedAt: string;
}
```

`StateMutation` 是一次状态变更提案或已接受变更，`StateProjection` 是便于读取的当前结果。

- 模型、插件和用户都只能提交 mutation，不能直接写 projection。
- Runtime 校验来源、Branch、权限和预期版本后，才接受 mutation。
- projection 损坏时，可以按有效事件和 mutation 重建。
- `namespace` 用于隔离核心状态和插件状态，但不能绕过核心提交闸门。

### 6.6 Checkpoint

```ts
interface Checkpoint {
  id: string;
  storyId: string;
  branchId: string;
  sequence: number;
  kind: "bootstrap" | "turn";
  turnId?: string;
  sceneId?: string;
  stateVersion: number;
  resourceRevisionSnapshot: unknown;
  controlVersionSnapshot: unknown;
  pluginStateVersionSnapshot: unknown;
  createdAt: string;
}
```

Checkpoint 是分叉、恢复和重试的稳定基准。它不要求复制所有状态，只需要能够确定：截至哪个事件、使用哪些资源版本、拥有哪一组状态和插件版本。

## 7. 认知层

### 7.1 ActorMemory

```ts
interface ActorMemory {
  id: string;
  storyId: string;
  branchId: string;
  subjectActorId: string;
  sourceEventIds: string[];
  sourceTurnId: string;
  kind: "knowledge" | "belief" | "suspicion" | "experience" | "personal_summary";
  content: string;
  confidence?: number;
  status: "active" | "stale" | "revoked";
  validFromSequence?: number;
  validUntilSequence?: number;
  createdAt: string;
}
```

记忆永远属于一个角色：

- 不设计共享记忆实体。
- 同一事件可以为不同角色生成不同记忆，也可以不给某个角色生成记忆。
- `belief` 和 `suspicion` 不能覆盖客观事件。
- 记忆修改应追加来源明确的修正记录，并使旧版本失效或标记过时。
- 子 Branch 只继承分叉点之前的记忆，之后的记忆完全隔离。

### 7.2 Summary

```ts
interface Summary {
  id: string;
  storyId: string;
  branchId: string;
  level: "turn" | "scene" | "arc" | "story";
  coveredThroughSequence: number;
  sourceTurnIds: string[];
  content: string;
  status: "active" | "superseded" | "invalid";
  generatedBy?: string;
  createdAt: string;
}
```

摘要必须记录覆盖范围。摘要不是事实来源，不能替代事件、状态和角色记忆。

### 7.3 ContextSnapshot

```ts
interface ContextSnapshotRecord {
  id: string;
  storyId: string;
  branchId: string;
  turnId: string;
  attemptId: string;
  role: "director" | "actor" | "chronicler";
  actorId?: string;
  checkpointId: string;
  sourceVersions: Record<string, string>;
  items: unknown[];
  renderedMessages: unknown[];
  estimatedTokens: number;
  omittedItemIds: string[];
  leakageCheck: "passed" | "failed";
  createdAt: string;
}
```

ContextSnapshot 用于模型请求审计、失败重试和泄漏排查。它不是故事事实，也不参与 Branch head。

MVP 默认保存完整作者指令、角色私有上下文、材料来源、渲染消息和裁剪结果；不加密、不自动过期，所有快照共用 300 MB 配额。用户可以手动清理，达到配额时不自动删除旧快照，新快照保存失败并提示清理空间。

## 8. 执行层

### 8.1 ScenePlan

```ts
interface ScenePlanRecord {
  id: string;
  turnAttemptId: string;
  basedOnCheckpointId: string;
  participantIds: string[];
  planPayload: unknown;
  status: "active" | "completed" | "invalidated" | "discarded";
  createdAt: string;
}
```

Plan 是导演的临时计划。它不能作为已发生事实，也不能直接成为角色记忆来源。

### 8.2 ModelRequestAttempt

```ts
interface ModelRequestAttempt {
  id: string;
  turnAttemptId: string;
  role: "director" | "actor" | "chronicler" | "auxiliary";
  actorId?: string;
  contextSnapshotId: string;
  provider: string;
  model: string;
  status: "queued" | "running" | "completed" | "failed" | "cancelled";
  finishReason?: string;
  usage?: unknown;
  errorCode?: string;
  startedAt?: string;
  endedAt?: string;
}
```

模型请求记录输入快照和结果状态，但模型请求本身不代表剧情已经发生。

### 8.3 ToolInvocation 和 Artifact

```ts
interface ToolInvocation {
  id: string;
  turnAttemptId?: string;
  toolId: string;
  input: unknown;
  output?: unknown;
  status: "running" | "completed" | "failed" | "cancelled";
  sourceActorId?: string;
  createdAt: string;
}

interface Artifact {
  id: string;
  storyId: string;
  branchId: string;
  turnId?: string;
  sourceEventIds: string[];
  sourceSegmentId?: string;
  kind: "message" | "chapter" | "image" | "audio" | "file";
  storageRef?: string;
  metadata?: unknown;
  status: "draft" | "committed" | "orphaned";
  createdAt: string;
}
```

媒体和小说改写结果是 Artifact。Artifact 的展示状态不能反过来改变 NarrativeEvent；新增剧情必须经过明确采纳和 Turn 提交。

### 8.4 RuntimeEvent

RuntimeEvent 保存执行审计和客户端恢复所需事件：

```ts
interface RuntimeEvent {
  id: string;
  storyId?: string;
  branchId?: string;
  turnId?: string;
  attemptId?: string;
  type: string;
  schemaVersion: string;
  sequence?: number;
  payload: unknown;
  occurredAt: string;
}
```

RuntimeEvent 和 NarrativeEvent 分开：

- `beat.accepted`、`request.failed`、`turn.interrupted` 是执行事件，不占用正式故事顺序。
- `turn.committed` 可以作为运行通知，但正式事实仍以 NarrativeEvent、StateMutation、ActorMemory 和 Branch head 的提交结果为准。
- 流式 delta 可以压缩或过期，不成为事实来源。

## 9. Turn 提交事务

一个 Turn 正式提交时，SQLite 事务必须同时完成：

1. 校验 Branch head、状态版本、控制版本和提交幂等键。
2. 写入本 Turn 的 NarrativeEvent。
3. 写入已接受的 StateMutation。
4. 更新 PublicState、角色状态和插件状态投影。
5. 写入 ActorMemory 变更。
6. 更新 Turn、Branch head 和 Checkpoint。
7. 写入摘要、全文索引等异步任务记录。

任何一个必需步骤失败，整个正式提交回滚。临时 Beat 和模型输出可以保留在 TurnAttempt 中，状态变为“待整理”或“待恢复”。

耗时的模型请求、网络工具、生图和摘要生成不在正式提交事务内部执行。

## 10. 查询边界

### 10.1 正式历史查询

普通故事历史只返回：

- 已提交 Turn。
- 已提交 NarrativeEvent。
- 已提交 Artifact。
- 当前有效的状态和记忆投影。

除非用户明确打开执行详情，否则不显示 Director Plan、模型请求、流式草稿和被回退的 Beat。

### 10.2 分支查询

分支查询必须带一个 Branch 和历史位置：

```text
当前 Branch 的自身记录
+ 父 Branch 在 forkCheckpoint 之前的记录
+ 更早祖先 Branch 在各自分叉点之前的记录
```

不能使用父 Branch 当前 head 的缓存冒充子 Branch 的历史。缓存键至少包含 `branchId`、`checkpointId`、资源版本和状态版本。

### 10.3 角色知识查询

Actor 查询只返回：

- 该角色自己的 ActorMemory。
- 该角色有资格观察到的正式事件结果。
- 当前公共状态中对该角色可见的部分。
- 适用的角色卡、WorldRule 和 Worldbook 条目。

查询先做 Branch 和权限过滤，再做关键词或全文排序。任何重排器、Archivist 或向量索引都不能访问过滤前的全集。

## 11. MVP 存储分层

首版可以采用以下方式：

| 数据 | MVP 存储 |
| --- | --- |
| Story、Branch、Scene、Actor、Turn | SQLite 表 |
| Event、Mutation、Memory、Summary | SQLite 表，JSON 字段保存扩展内容 |
| TurnWorkingState | SQLite 临时状态表或 JSON 快照 |
| ContextSnapshot | SQLite 元数据 + 完整消息/材料，可压缩保存 |
| 图片、音频、文件 | `$APP_DATA_DIR/media` 文件，SQLite 保存引用 |
| 插件包 | `$APP_DATA_DIR/plugins`，SQLite 保存安装记录 |
| 全文检索 | SQLite FTS5 `trigram`；不足 3 个字符的查询回退为受限关键词/`LIKE` 查询 |
| 向量索引 | LanceDB 本地目录 `$APP_DATA_DIR/vector`；SQLite 保存事实来源和权限元数据 |

不要把图片、音频和大模型完整响应全部塞入 SQLite。数据库保存可审计的引用、摘要和状态，文件系统保存媒体和必要的大对象。

## 12. 幂等、版本和并发

所有会产生正式变化的命令都需要幂等键。至少包括：

- 创建 Turn。
- 提交 Turn。
- 状态修正。
- 创建 Branch。
- 设置角色控制状态。
- 采纳中断前缀。

所有正式写入都需要检查：

- `branchId` 是否匹配。
- 预期 head/状态版本是否仍然有效。
- Attempt 是否仍然拥有执行租约。
- 控制版本和资源版本是否没有变化。

MVP 每个 Branch 只允许一个活动写入执行。另一个 Turn 必须排队或要求用户停止当前 Turn。

## 13. 删除、归档和失效

- 已提交事件不做物理删除。
- Story、Branch、Scene、资源和插件优先使用归档状态。
- 用户删除媒体时，必须保留 Artifact 的失效记录。
- 插件卸载后保留插件状态，标记为不可用。
- 摘要、记忆和投影失效时保留旧版本，便于审计和重建。
- 临时流式草稿在生命周期结束后可以清理，但必须保留对应的中断或失败 RuntimeEvent。

## 14. MVP 必须实现的对象

第一阶段至少实现：

1. `Story`
2. `Branch`
3. `Scene`
4. `ActorDefinition` / `ActorInstance`
5. `ActorControlAssignment`
6. `Turn` / `TurnAttempt` / `Beat`
7. `NarrativeEvent`
8. `StateMutation` / `StateProjection`
9. `ActorMemory`
10. `Summary`
11. `Checkpoint`
12. `ModelConnection` / `ExecutionProfile`
13. `ModelRequestAttempt`
14. `RuntimeEvent`
15. `Asset` / `AssetRevision` / `StoryResourceBinding`
16. `AuthCredential` / `AuthSession`

以下可以先使用简化实现：

- `ToolInvocation` 先只保存基本输入、输出和状态。
- `Artifact` 先支持文本和文件引用。
- `ContextSnapshot` 默认保存完整的版本、材料、渲染消息和裁剪结果；总配额为 300 MB，不自动过期，用户可以手动清理，过大时可以压缩保存。
- 插件状态先统一使用 JSON payload，不做复杂 schema 注册界面。

## 15. 已确定边界

1. 角色位置、物品和关系使用核心状态 JSON Schema 表达，并由 `StateMutation` 统一提交。
2. MVP 只有一个账号，不设计多用户 Story 权限字段。
3. 向量索引默认使用 LanceDB；索引损坏时可从 SQLite 事实和来源记录重建。
4. 媒体文件清理、备份和导出可以独立演进，但不能删除仍被 Artifact 引用的正式文件。
5. 插件状态使用命名空间、schemaVersion 和迁移入口；复杂迁移表不是 MVP 必需。

## 16. 验收场景

| ID | 场景 | 必须满足的结果 |
| --- | --- | --- |
| D01 | Beat 生成后断流 | Beat 和草稿可恢复，但不出现在正式历史、ActorMemory 或 Branch head |
| D02 | Turn 正常提交 | 事件、状态、记忆、Turn 状态和 Checkpoint 一起成功或一起失败 |
| D03 | Chronicler 失败 | 保留 TurnAttempt 临时数据，不写正式事件和角色记忆 |
| D04 | 从 E3 创建 Branch B | B 只继承 E3 及以前的祖先数据，不读取父 Branch 的 E4/E5 |
| D05 | Alice 和 Bob 对同一事件有不同认知 | 保存两条独立 ActorMemory，不能合并成共享记忆 |
| D06 | 重试同一模型请求 | 新建 ModelRequestAttempt，使用记录的上下文版本，不重复提交 Turn |
| D07 | 用户修改事实 | 追加修正来源，旧事件仍可审计，相关投影和摘要失效或重建 |
| D08 | 用户接管 Bob | 增加控制版本，旧 Plan 失效，Bob 不产生自动 Beat |
| D09 | 删除插件 | 插件数据保留并标记不可用，不影响核心事件回放 |
| D10 | 回放历史 | 只读取事件和派生数据，不重新调用模型、工具或生图服务 |
